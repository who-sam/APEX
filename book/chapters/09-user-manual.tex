\chapter{User Manual}
\label{ch:user-manual}

This chapter walks through APEX from the user's chair. The screenshots are taken from a local instance brought up by \texttt{./start.sh} with the seed data set described in \Cref{ch:testing}: \emph{Dr.~Demo} as a teacher, \emph{Sam Student} as a student, one demo class, and one each of a coding, MCQ, and written exam. The screen captures are at 1440$\times$900 with the browser chrome cropped. Every screen is reachable from the routes documented in \Cref{fig:F5.11}.

\paragraph{A note on availability.} The screenshots referenced below are produced from a running deployment and live in \texttt{book/figures/screenshots/}. When this manuscript is built without that directory populated --- for example, on a fresh clone --- LaTeX will substitute a placeholder rectangle and the prose still flows. The capture script and seed data are documented in \Cref{appendix:screenshots-extra}.

\section{Teacher: managing classes}

From the teacher dashboard, \emph{Courses} opens \texttt{/dashboard/courses}, listing owned classes. \emph{New class} pops a dialog (name, optional section); on save, the class appears with its 8-character invite code (\Cref{fig:F9.5}). Sharing the invite code with students is the only enrollment mechanism.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.95\linewidth]{F9.5_class-list-teacher.png}
  \caption{Teacher's class list with invite codes.}

Clicking a class opens its detail screen (\Cref{fig:F9.6}). The detail shows the roster, the assigned exams, and the announcements feed. The teacher can rename the class, change cover image, toggle \emph{Grades announced}, change the passing threshold, post an announcement, or remove a member.

\section{Teacher: building an exam}

\emph{Exams} (\texttt{/dashboard/exams}) lists owned exams with status badges (Draft, Upcoming, Active, Completed). \emph{New exam} opens the exam builder at \texttt{/dashboard/exam-builder} (\Cref{fig:F9.7}). The header collects metadata; a left rail lists the questions; the right pane edits the selected question.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.95\linewidth]{F9.7_exam-builder.png}
  \caption{Exam builder.}
  \label{fig:F9.7}
\end{figure}

Adding a coding question (\Cref{fig:F9.8}) requires a title, a Markdown description, the time and memory limits, optional starter code, and a list of test cases. Each test case is sample or hidden; sample test cases are visible to the student during the attempt. Adding an MCQ (\Cref{fig:F9.9}) is a list of options with a per-option \emph{Correct} checkbox; the editor enforces \emph{at least one correct} before allowing publish. Adding a written question (\Cref{fig:F9.10}) collects the prompt, the rubric, and the maximum word count; the \emph{Require manual grading} toggle is on by default.

\section{Other surfaces}

\paragraph{Notifications.} The bell icon in the top bar opens the notifications popover; the \emph{Notifications} page (\texttt{/dashboard/notifications}) lists everything historically. Each notification carries a deep link.

\paragraph{Profile and settings.} \emph{Profile} (\texttt{/dashboard/profile}) edits the display name, bio, and avatar. \emph{Settings} (\texttt{/dashboard/settings}) toggles email vs.\ in-app notifications per channel, including the per-user \emph{exam reminder email} opt-in that the reminder scheduler honours.

\paragraph{Question bank.} \emph{Question bank} (\texttt{/dashboard/question-bank}, teacher only) lets the teacher save problems for reuse, organise them in folders, and import them into a new exam. The bank shares the \texttt{problems} table with the exam-attached problems but uses \texttt{is\_bank = true} to scope queries.

\section{Summary}

The system is structured as one teacher path (build $\to$ assign $\to$ grade $\to$ announce) and one student path (join $\to$ take $\to$ review). The screenshots in this chapter are the load-bearing user-facing artefacts; the next chapter measures the system's behaviour under realistic load.
